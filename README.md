# Pensieve

A production-ready local agent for [Fireflies.ai](https://fireflies.ai) meeting transcripts.
It watches a local folder where Fireflies auto-saves meeting transcripts as `.md` files (and
optionally polls the Fireflies GraphQL API as a secondary source), analyzes each transcript with
the local **GitHub Copilot CLI**, and produces a rich, per-meeting output folder: a summary,
agreements/decisions, open questions, next actions per participant, AI-generated tags, a
per-meeting keyword vocabulary, and Mermaid diagrams whenever a flow/architecture/component
relationship is actually discussed. It also maintains a **global keyword vocabulary** aggregated
across all processed meetings.

The agent is implemented as a set of [dotnet-script](https://github.com/dotnet-script/dotnet-script)
C# scripts — there is no `.csproj`/build step, just `dotnet-script` running `.csx` files directly.
Analysis is generated by shelling out to the local Copilot CLI (`copilot -p ...`) rather than
calling an LLM HTTP API directly, so no OpenAI/LLM API key is needed.

## Features

- **Primary source — folder watch**: watches a local folder (`WATCH_FOLDER`) for new `.md`
  transcript files that Fireflies auto-saves there, either as a one-shot scan (`sync`/`run`) or
  live via `FileSystemWatcher` (`watch`), debounced so a file is only picked up once Fireflies has
  finished writing it.
- **Native Fireflies export layout support**: Fireflies' own local backup/export drops two
  sibling folders — `Transcripts/` (raw transcript per meeting) and `Summaries/` (Fireflies' own
  AI summary, which reliably embeds the Fireflies meeting ID/link, title, and date). Point
  `WATCH_FOLDER` at `Transcripts/` and (optionally, but recommended) `SUMMARY_FOLDER` at the
  sibling `Summaries/` folder — the agent will pair each transcript with its matching summary
  file by filename to reliably resolve the Fireflies ID/title/date, **using it only for that
  metadata**. The summary's text is never fed into the analysis; Copilot CLI always analyzes only
  the raw transcript file, preserving the no-hallucination/single-transcript-scope guarantee.
- **Secondary source — Fireflies API (optional)**: can additionally/instead fetch transcripts via
  the Fireflies GraphQL API (`ENABLE_FIREFLIES_API_SOURCE=true`), resuming from the last
  processed date automatically.
- **Never modifies the original transcript**: the source `.md` file dropped by Fireflies (or
  fetched from the API) is never edited, moved, or deleted from disk — only copied verbatim into
  a new per-meeting output folder.
- **One output folder per meeting**, under
  `OUTPUT_DIR/<YYYY-MM-DD>--<HHmm>--<safe-title>--<id>/` (time is Bratislava-local, so same-day
  meetings sort correctly in a plain alphabetical folder listing):
  - `transcript.md` — verbatim copy of the source transcript text.
  - `note.md` — YAML frontmatter with **only `tags`** (rendered in **camelCase**, e.g.
    `releasePlanning`; no duplication with the body — title, date, Fireflies ID/link live solely
    in the body header) plus: a body header (title, date in Bratislava time, participants,
    Fireflies link/ID), summary, agreements, open questions, next actions (owner/due when
    explicitly stated), diagram links, and keywords (also rendered in **camelCase**, e.g.
    `coldBrew`). Tags are capped at **5 per meeting**, generated as three facets and then
    flattened: one **meeting type** (e.g. standup, planning, one-to-one), one **category**
    (e.g. technology, design, team, business), and 1-3 **topics** naming the key subject(s)
    actually discussed — keeping tagging consistent instead of an unbounded pile of
    near-duplicate phrases.
  - `diagrams/*.md` — one file per Mermaid diagram, **only created when the transcript explicitly
    discusses a flow, architecture, or component relationship**.
  - `keywords.json` — this meeting's own tag/keyword vocabulary, in canonical (non-camelCase)
    casing (tags and keywords alike).
  - `metadata.json` — the application version that generated this output, MD5 checksums of
    `note.md` and `transcript.md` (for integrity/traceability, e.g. detecting later manual edits),
    and a `speakerStatistics` array (see below).
- **Per-speaker statistics** (`metadata.json`'s `speakerStatistics` array, one entry per speaker):
  - `speakingTimeSeconds` / `speakingTimePercent` / `turnCount` — 100% deterministic, code-computed
    from turn timestamps (never LLM-derived): each turn's duration is the next turn's start time
    minus its own start time, summed per speaker; a speaker's very last turn in the transcript
    contributes 0 seconds (no later timestamp to bound it — a minor, consistent undercount rather
    than a guess).
  - `clarity` / `informativeness` / `engagement` (integer 1–5) and `rationale` — LLM-assessed via
    the Copilot CLI, grounded strictly in what that speaker actually said in this transcript; the
    model only rates speakers who actually appear/speak, and the rationale must cite real content
    from the transcript (no outside assumptions, no invented speakers). These fields are `null`
    when the analysis didn't return a rating for that speaker (e.g. very short transcripts) —
    never fabricated.
  - A speaker present in only the timing data or only the quality ratings still appears in the
    array, with the fields it does have — the two sources are merged by speaker name
    (case-insensitive).
- **Global vocabulary** (`data/vocabulary.json`): a pure, mechanical aggregation of every
  meeting's already-generated tags/keywords (counts + linked meeting IDs). It is never itself
  re-summarized by the LLM, preserving the no-hallucination guarantee across meetings.
  Since AI-generated terms can occasionally be misspelled or inconsistent between meetings, the
  file also has a user-editable `aliases` section — `{ "canonicalTerm": ["variant1", "variant2"]
  }` — that you can hand-edit at any time; on the next run, any incoming tag/keyword matching a
  listed variant (case-insensitively) is automatically merged into its canonical entry. The app
  only ever reads and preserves your aliases — it never resets or overwrites them.
- **Strict anti-hallucination scope**: the Copilot CLI prompt forbids inventing content and
  forbids using any information beyond the current transcript — no cross-meeting knowledge. Any
  field not explicitly present falls back to the literal `not specified` (or an empty list),
  enforced in code, not left to the model's discretion.
- **Optional, config-gated Fireflies deletion**: after a meeting is fully and successfully
  processed, the agent can delete it from Fireflies via the API
  (`FIREFLIES_AUTO_DELETE_AFTER_PROCESSING=true`, **disabled by default**). The Fireflies ID is
  read from the dropped file if embedded (YAML frontmatter or a `fireflies.ai/view/...` URL in
  the body); otherwise it's best-effort resolved via the API by title+date. If no ID can be
  resolved, deletion is skipped and a warning is logged — **never guessed**.
- **Optional, config-gated exports**, both off by default:
  - **Obsidian**: copies the full meeting folder into a configured vault subfolder.
  - **Notion**: creates one page per meeting (title, tags, meeting date, import date, summary,
    agreements, open questions, next actions, diagrams as fenced `mermaid` code blocks, keywords,
    related meetings) via the Notion API. The target Notion database must already have these
    exact properties (property *names* are hardcoded, not auto-created — Notion's API rejects
    writes to properties that don't exist) before enabling `ENABLE_NOTION_EXPORT`:
    | Property name | Type |
    | --- | --- |
    | `Name` | Title (Notion's default title property, renamed if needed) |
    | `Tags` | Multi-select |
    | `Imported At` | Date |
    | `Meeting Date` | Date |

    Add any missing ones via Notion → database → `+` → matching property type. A `400 validation_error`
    with a message like `"Meeting Date is not a property that exists"` means one of these is missing
    or misnamed in your database.
- **Optional, config-gated related-meeting linking** (`ENABLE_MEETING_LINKING=true`, disabled by
  default): purely mechanical (no LLM cross-meeting reasoning, preserving the anti-hallucination
  guarantee) — links a meeting to other meetings that are either part of the same **recurring
  series** (e.g. daily standups, weekly syncs — detected by normalizing the title and stripping
  embedded dates/weekdays/times) or share at least `MEETING_LINK_MIN_SHARED_TAGS` (default 2)
  tags/keywords with it (e.g. several differently-titled meetings about the same initiative).
  Maintains a mechanical index (`data/meetings-index.json`) of every linked meeting's title,
  date, folder, tags, and keywords — never re-analyzed by the LLM. Adds a **"Related Meetings"**
  section to each `note.md` (relative links + dates, capped at `MEETING_LINK_MAX_RELATED`, default
  15) and `seriesKey`/`relatedMeetingIds` to `metadata.json`. When combined with
  `ENABLE_NOTION_EXPORT`, related meetings are also listed as a text block in the Notion page;
  additionally setting `ENABLE_NOTION_RELATION_LINKS=true` sets a native Notion **relation**
  property (name configurable via `NOTION_RELATION_PROPERTY_NAME`, default `Related Meetings`) —
  this requires you to first add a self-relation column with that exact name to your Notion
  database (Notion → database → `+` → property type "Relation" → relate to the same database).
- **Optional macOS Notification Center alert** (`ENABLE_MACOS_NOTIFICATIONS=true`, disabled by
  default): shows a native notification (meeting title + summary snippet) as soon as a meeting
  finishes processing, using the built-in `osascript`/AppleScript — no extra dependency (e.g.
  `terminal-notifier`) required. Optional `MACOS_NOTIFICATION_SOUND` to play a sound. No-ops
  (with a log warning) on non-macOS systems, and never affects processing/state on failure.
- Idempotent, resumable state (`data/state.json`) tracks per-meeting analysis/delete/export
  status independently, so a crash or transient failure at any step is safely retried on the next
  pass without reprocessing completed work.
- **All dates/times use the Europe/Bratislava timezone** (correctly handling CET/CEST
  daylight-saving), regardless of the machine's local timezone or the source data's original
  timezone — used consistently for output folder naming and the `note.md` date display.
- Robust structured logging (console + daily rolling log file under `data/logs/`) and automatic
  retry with exponential backoff on transient failures (HTTP calls and Copilot CLI invocations).
- Fully configured through a single `.env` file — no secrets in code, no CLI flags for config.

## Project layout

```
pensieve/
  main.csx                        # CLI entry point: `sync`, `watch`, `run`
  src/
    Config.csx                     # .env loading & validation (new source/export/delete flags)
    Version.csx                     # AppVersion constant, recorded into each metadata.json
    DateTimeHelper.csx               # UTC -> Europe/Bratislava conversion helper
    KeywordFormatter.csx              # camelCase rendering for note.md tags/keywords (display-only)
    Logging.csx                     # leveled logger (console + file)
    HttpRetry.csx                    # HTTP retry/backoff helper
    Models.csx                       # Transcript, TranscriptAnalysis, DiagramItem, etc.
    FolderWatcher.csx                 # watches WATCH_FOLDER for new .md files (scan + live watch)
    TranscriptFileParser.csx           # parses a dropped .md: text, embedded Fireflies id/url
    FirefliesClient.csx                 # GraphQL: fetch, title+date ID resolution, delete mutation
    CopilotCliClient.csx                  # strict-JSON analysis via the local `copilot` CLI
    SpeakerTimingAnalyzer.csx               # deterministic per-speaker speaking time/turn count
    StateStore.csx                         # data/state.json — per-meeting idempotency tracking
    MeetingFolderWriter.csx                 # writes the per-meeting output folder
    GlobalVocabularyStore.csx                # data/vocabulary.json — cross-meeting aggregation
    SeriesKeyGenerator.csx                    # optional: normalizes titles into series keys
    MeetingIndexStore.csx                      # optional: data/meetings-index.json — linking index
    MeetingLinker.csx                           # optional: mechanical related-meeting matching
    ObsidianExporter.csx                      # optional: copies meeting folder into a vault
    NotionExporter.csx                          # optional: creates a Notion page per meeting
    MacNotifier.csx                               # optional: macOS Notification Center alert
    SafeFileName.csx                             # meeting-title slugification
    Orchestrator.csx                              # wires sources -> analysis -> outputs -> state
  tests/
    run-tests.csx              # custom test runner (no external test framework)
    TestKit.csx                 # assertion helpers + fake HttpMessageHandler for mocking
    test-fixtures/               # mocked Fireflies responses + Copilot CLI response fixtures
    test-*.csx                    # tests per module
  data/                       # created at runtime: state.json, vocabulary.json,
                              # meetings-index.json (if enabled), logs/ (gitignored)
  .env.example
  .gitignore
```

## Quick install (macOS)

A one-shot installer script (`install.sh`) is included for macOS: it installs Homebrew, the
.NET SDK, `dotnet-script`, and the GitHub Copilot CLI if missing; clones (or updates) this repo;
interactively builds your `.env` from `.env.example`; runs the test suite as a sanity check; and
writes/loads a `launchd` agent so Pensieve runs continuously in the background.

```bash
curl -fsSL https://raw.githubusercontent.com/lukasblaho/pensieve/master/install.sh | bash
```

Or, if you've already cloned the repo:

```bash
./install.sh
```

Useful flags/env vars:

- `--non-interactive` — never prompt; uses env vars (`WATCH_FOLDER`, `SUMMARY_FOLDER`,
  `OUTPUT_DIR`, `POLL_INTERVAL_MINUTES`, ...) or `.env.example` defaults as-is. The launchd agent
  is written but **not** auto-loaded unless you also set `PENSIEVE_AUTO_LOAD_LAUNCHD=true` (an
  explicit opt-in, since loading it starts a real background process immediately).
- `--skip-launchd` — install/configure only, skip the background service setup entirely.
- `--skip-clone` — reuse an existing checkout instead of cloning/pulling.
- `PENSIEVE_INSTALL_DIR` (default `$HOME/pensieve`), `PENSIEVE_REPO_URL`, `PENSIEVE_RUN_MODE`
  (`watch` or `run`, default `watch`) — control where it's installed and how the launchd agent
  invokes it.

Re-running the installer later (e.g. `PENSIEVE_INSTALL_DIR=~/pensieve ./install.sh`) safely
pulls the latest changes and re-checks prerequisites; it never overwrites an existing `.env`.

## Prerequisites

- [.NET SDK](https://dotnet.microsoft.com/) (8.0+ recommended).
- The `dotnet-script` global tool:

  ```bash
  dotnet tool install -g dotnet-script
  # Ensure the dotnet tools folder is on your PATH, e.g.:
  export PATH="$PATH:$HOME/.dotnet/tools"
  ```

- The [GitHub Copilot CLI](https://github.com/github/copilot-cli), installed and authenticated:

  ```bash
  copilot login
  ```

  The agent shells out to `copilot -p "..."` to analyze transcripts, so it must be reachable on
  `PATH` (or point `COPILOT_EXECUTABLE` in `.env` at its full path).

## Setup

1. Copy the example environment file and configure it (see `.env.example` for the full list of
   options and inline documentation):

   ```bash
   cp .env.example .env
   ```

   At minimum, set `WATCH_FOLDER` to the folder where Fireflies drops `.md` transcripts, and
   `OUTPUT_DIR` for the generated per-meeting folders. If you're using Fireflies' native local
   export/backup (with sibling `Transcripts/` and `Summaries/` folders), also set
   `WATCH_FOLDER` to the `Transcripts/` folder and `SUMMARY_FOLDER` to the sibling `Summaries/`
   folder for reliable ID/title/date resolution. All optional features (Fireflies API
   source, auto-delete, Obsidian export, Notion export) are **disabled by default** — enable each
   explicitly via its own flag.

   > **If `WATCH_FOLDER` lives inside a cloud-sync client folder (e.g. Google Drive Desktop,
   > OneDrive, Dropbox):** by default these clients can stream files on demand, meaning a file
   > can appear in the folder before its content has actually finished downloading locally.
   > Pensieve reads files directly off disk and does not fetch cloud-only content itself, so a
   > transcript picked up too early could be processed with empty/partial content. Configure the
   > watched folder (and its `Summaries/` sibling, if used) to always keep files downloaded
   > locally instead of streaming them on demand — e.g. in Google Drive Desktop, right-click the
   > folder and choose **"Make available offline"** (may also be labeled **"Available
   > offline"**/"Mirror" depending on version); in OneDrive, disable **Files On-Demand** for that
   > folder or mark it "Always keep on this device".

2. Run a single sync pass (scans the watch folder — and the Fireflies API if enabled — for any
   new/changed transcripts, processes them, then exits):

   ```bash
   dotnet script main.csx -- sync
   ```

3. Or run continuously, polling every `POLL_INTERVAL_MINUTES`:

   ```bash
   dotnet script main.csx -- run
   ```

4. Or live-watch the folder (processes anything already present, then reacts to new files as
   Fireflies drops them):

   ```bash
   dotnet script main.csx -- watch
   ```

   Press `Ctrl+C` to stop gracefully in any mode.

## Running the tests

Tests use a custom, dependency-free runner (dotnet-script doesn't integrate with `dotnet test`/xUnit)
with mocked Fireflies/Notion HTTP responses and a fake `copilot` executable (a small shell script)
standing in for the real Copilot CLI — no real network calls, API keys, or Copilot CLI
installation required:

```bash
dotnet script tests/run-tests.csx
```

Exits with code `0` if all assertions pass, `1` otherwise.

## Scheduling on macOS

> **Note:** `cron` and `launchd` run with a minimal environment, so both `dotnet-script` and
> `copilot` must be explicitly included in `PATH` (they won't inherit your interactive shell's
> PATH). Adjust the paths below to match `which dotnet-script` and `which copilot` on your machine.

### Option A: cron

```cron
*/15 * * * * cd /path/to/pensieve && /usr/bin/env PATH="$PATH:$HOME/.dotnet/tools:/opt/homebrew/bin" dotnet-script main.csx -- sync >> data/logs/cron.log 2>&1
```

### Option B: launchd (recommended)

Create `~/Library/LaunchAgents/com.pensieve.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>com.pensieve</string>

  <key>ProgramArguments</key>
  <array>
    <string>/usr/bin/env</string>
    <string>dotnet-script</string>
    <string>main.csx</string>
    <string>--</string>
    <string>watch</string>
  </array>

  <key>WorkingDirectory</key>
  <string>/path/to/pensieve</string>

  <key>EnvironmentVariables</key>
  <dict>
    <key>PATH</key>
    <string>/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/Users/YOUR_USER/.dotnet/tools</string>
  </dict>

  <key>RunAtLoad</key>
  <true/>
  <key>KeepAlive</key>
  <true/>

  <key>StandardOutPath</key>
  <string>/path/to/pensieve/data/logs/launchd.out.log</string>
  <key>StandardErrorPath</key>
  <string>/path/to/pensieve/data/logs/launchd.err.log</string>
</dict>
</plist>
```

Load/unload:

```bash
launchctl load ~/Library/LaunchAgents/com.pensieve.plist
launchctl unload ~/Library/LaunchAgents/com.pensieve.plist
```

(`run` with `POLL_INTERVAL_MINUTES` also works instead of `watch`, if you prefer periodic
polling over live filesystem events.)

## Notes on behavior

- **Never modifies or deletes the original transcript file on disk.** The source `.md` file
  Fireflies drops locally is only ever read, then copied — verbatim — into the per-meeting output
  folder. The optional Fireflies API deletion feature deletes the transcript *from Fireflies*
  (via its API), never the local file.
- **Idempotency**: each meeting's analysis, Fireflies-deletion, and each export step are tracked
  independently in `data/state.json`. A folder-sourced file is only reprocessed if its content
  hash changes (i.e. the file was actually edited); an API-sourced transcript is identified by
  its immutable Fireflies ID.
- **No invented content**: the Copilot CLI prompt explicitly forbids inventing agreements,
  owners, due dates, tags, keywords, or diagrams, and scopes analysis strictly to the current
  transcript (no cross-meeting knowledge). Any field the model still fails to specify is
  normalized in code to the literal string `not specified` (or an empty list) — this fallback
  isn't left to the model's discretion.
- **Diagrams are conditional**: Mermaid diagrams are only produced when the transcript explicitly
  discusses a process flow, system architecture, or component/data relationship — never forced.
- **Global vocabulary is pure aggregation**: `data/vocabulary.json` only counts and links
  meeting IDs to tags/keywords that each meeting's own (already-validated) analysis produced. It
  is never itself sent back through the LLM, so nothing can be hallucinated across meetings.
  You can freely hand-edit the `aliases` section to merge AI misspellings/inconsistent variants
  into a single canonical term — the app treats it as user-owned data and only ever reads it.
- **Related-meeting linking is also pure aggregation**: like the global vocabulary,
  `data/meetings-index.json` and the "Related Meetings" links it produces are 100% mechanical —
  matching on normalized titles (series) and shared tags/keywords already produced per-meeting.
  No transcript content from other meetings is ever fed back into the LLM. The feature only
  starts linking meetings processed after it was enabled — it never retroactively scans/rewrites
  meetings processed before `ENABLE_MEETING_LINKING` was turned on.
- **Meeting folder integrity**: each `metadata.json` records the app version and MD5 checksum of
  `note.md`/`transcript.md` at generation time, so you can later detect whether either file was
  manually edited after the fact, or trace output back to the app version that produced it.
- **Deletion and exports are all opt-in and off by default**, since they are
  destructive/external-side-effect operations. Fireflies deletion additionally requires a
  successfully resolved transcript ID — the agent never guesses an ID to justify a deletion.
- **Output language**: the source transcript may be in English, Slovak, or Czech (Fireflies
  doesn't translate), but the generated summary, agreements, open questions, and next actions are
  always written in English — enforced via the system prompt sent to the Copilot CLI. The
  `transcript.md` verbatim copy is never translated or altered.
- **Timezone**: all dates/times shown or used for folder naming (meeting date/time, folder
  `HHmm` segment) are converted to Europe/Bratislava local time, correctly handling CET/CEST
  daylight-saving — independent of the machine's own local timezone or the original source data's
  timezone.
